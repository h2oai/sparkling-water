# Sparkling Water – Repository Index

Purpose: a dense map of the codebase for refactoring work. Facts here were verified on 2026-11-06
against commit `1fc226532` (version `3.46.0.2-1-SNAPSHOT`, default Spark 3.5 / Scala 2.12.18, H2O 3.46.0.6).
Update this file when module boundaries or build mechanics change.

## 1. What the project is

Sparkling Water integrates H2O-3 (distributed ML engine) with Apache Spark.
Core ideas:

- `H2OContext` (Scala, `core`) starts/attaches an H2O cluster and converts data both ways
  (`DataFrame`/`RDD`/`Dataset` <-> `H2OFrame`).
- Spark ML estimators (`ml`) train H2O models via H2O's REST API and return Spark ML `Model`s that
  wrap a **MOJO** (portable scoring artifact). Scoring (`scoring`) needs no running H2O cluster.
- Python (`py`, `py-scoring`) and R (`r`, `r-cran`) are thin wrappers over the JVM API via Py4J / sparklyr.
- Large parts of the ML API (algorithms, params, MOJO models, metrics) are **generated** from H2O's own
  parameter schemas by `api-generation`, for Scala, Python, and R.

Two backends:
- **Internal**: H2O nodes run inside Spark executors (`org.apache.spark.h2o.backends.internal`).
- **External**: H2O cluster runs separately on YARN/Kubernetes or started manually
  (`ai.h2o.sparkling.backend.external`).
All driver-to-H2O communication goes over REST (`RestCommunication`), not a shared JVM.

## 2. Build system (Gradle 7.6, multi-project)

- `settings.gradle` lists 26 subprojects; every name is prefixed `sparkling-water-` (e.g. `:sparkling-water-core`).
- `build.gradle` (root): defines `publishedProjects`, `scalaProjects`, `pythonProjects`, `rProjects`, `integTestProjects`,
  version resolution (`version` + `-<sparkMajor>` suffix), and loads `gradle-spark<X.Y>.properties` per Spark version.
- `gradle.properties`: `spark=3.5` (default target), `supportedSparkVersions=2.3 … 3.5`, H2O version,
  `pythonEnvironments`, `jettyVersion`, `mojoPipelineVersion`.
- `gradle-spark<X.Y>.properties`: per-Spark overrides (`sparkVersion`, `scalaVersion`, `minSupportedJavaVersion`,
  `fabricK8sClientVersion`, `supportedPythonVersions`, `databricksVersion`, EMR version).
- `gradle/*.gradle` shared scripts:
  - `scala.gradle` – scala plugin, forced Scala version, macro paradise plugin (<2.13), scalac flags,
    `testJar`/`sourcesJar`/`scaladocJar`, `testArchives` configuration, spotless (scalafmt + google-java-format),
    `checkScalaTestEnv` (requires `H2O_DRIVER_JAR` for external-backend tests).
  - `spark.gradle` – `SPARK_HOME` detection, `sparkHome`/`sparkMaster`, `checkSparkVersion`.
  - `utils.gradle` – helpers: `detectBackendClusterMode`, `getSparkSpecificSourceDir`,
    `getSparkSpecificResourceDir`, `getGitHash`, `getH2OBranch/Build`, S3 paths, download helpers.
  - `itest.gradle` (integTest source set), `bench.gradle`, `publish.gradle`, `release.gradle`, `python.gradle`, `r.gradle`.
- **Spark-version-specific sources**: a module may have `src/main/scala_spark_<X.Y>/` and `scala_spark_others/`
  (and `resources_spark_*`). Exactly one is picked per build via `getSparkSpecificSourceDir`.
  - `core`: `scala_spark_2.1`, `2.2`, `2.3`, `others` → `SparkTimeZone`, `SparkSpecificUtils`, Spark UI listener/plugin/store.
  - `utils`: `scala_spark_3.0`…`3.5`, `others` → Catalyst encoder/`expose` shims (`ai.h2o.sparkling.sql.*`, `org.apache.spark.sql.expose`).
- **Generated code**: `src-gen/` directories (git-ignored) in `ml`, `scoring`, `py`, `py-scoring`, `r`. Regenerated by
  `generateApi` / `generateAlgorithmApi` / `generateMOJOApi` / `generateConf` tasks that run
  `api-generation` runners before `compileScala`. Never edit `src-gen`; change templates/configurations instead.
- Common commands:

```
./gradlew build -x check                       # compile everything for default Spark
./gradlew :sparkling-water-core:test           # unit tests for one module
./gradlew :sparkling-water-ml:check            # build + tests
./gradlew test -Pspark=3.3                     # other Spark version (needs matching SPARK_HOME)
./gradlew spotlessApply                        # format (scalafmt, .scalafmt.conf, maxColumn=120)
./gradlew :sparkling-water-py:testPython       # pysparkling unit tests
./gradlew :sparkling-water-r:test              # rsparkling tests
./gradlew dist                                 # full distribution zip (dist/)
./gradlew integTest                            # integration tests (needs SPARK_HOME, sparkMaster)
```

- Backend for tests: system property `spark.ext.h2o.backend.cluster.mode=internal|external`
  (see `SparkTestContext.defaultSparkConf`).
- Formatting: spotless check runs in `check`. Scala files carry the ASF license header.

## 3. Module dependency graph (compile-time, `api`/`implementation`)

```
macros ──(compileOnly)──> core, ml, scoring
utils  <── extensions <── core <── ml <── examples
utils  <── repl       <── core
utils  <── scoring    <── ml
utils  <── api-generation ──(implementation)──> ml ; (compileOnly) scoring
ml + repl + core + extensions ──> assembly (shadow fat jar) ──> package, py, r, kubernetes, dist
scoring ──> assembly-scoring ──> scoring-package, py-scoring
extensions + utils ──> assembly-extensions (embedded jar shipped to external H2O nodes; sourcesJar depends on it)
core + utils ──> booklet, doc (doc generation runners)
benchmarks ──> core/ml (standalone Spark apps)
```

Spark, Hadoop, Scala, H2O (`h2o-core`, `h2o-algos`, …) are mostly `compileOnly`; `assembly/build.gradle`
has a long exclude list so the fat jar doesn't bundle what Spark provides.

## 4. Module-by-module

### `utils` (`ai.h2o.sparkling.utils`, `ai.h2o.sparkling.ml.utils`, `org.apache.spark.*`)
Leaf module, no SW deps. `SchemaUtils` (flattening nested schemas, used by converters and MOJO scoring),
`DatasetShape`, `DataFrameSerializer`/`JSONDataFrameSerializer` (params that hold DataFrames),
`Compression`, `Base64Encoding`, `ScalaUtils`, `SparkSessionUtils.active`, `CompatibilityObjectInputStream`.
`org.apache.spark.expose.{Logging,Utils}` and `org.apache.spark.sql.{DatasetExtensions,DataTypeExtensions,SWGenericRow}`
exist only to reach Spark-private APIs; Spark-version shims live in `scala_spark_*`.

### `macros` (`ai.h2o.sparkling.macros.DeprecatedMethodMacro`)
Scala macro used to mark deprecated API methods (compileOnly everywhere).

### `extensions` (`ai.h2o.sparkling.extensions.*`, `water.fvec`, `water.parser`)
Code that runs **inside H2O nodes** (registered via `META-INF/services/water.api.RestApiExtension`,
`water.api.Schema`, `water.server.ServletProvider`, `water.AbstractH2OExtension`).
- `rest/api/`: `ChunkServlet` (binary chunk upload/download), `ChunkCategoricalDomainsServlet`,
  `ImportFrameHandler` (InitializeFrame/FinalizeFrame/UploadPlan), `LogLevelHandler`,
  `VerificationHandler` (version/web-open checks), `SparklingWaterAvailableHandler`, `InternalUtilsServlet`, `Paths` (URL constants).
- `serde/`: `ChunkAutoBufferReader/Writer`, `ExpectedTypes`, `SerdeUtils` – the wire format for frame data.
- `stacktrace/StackTraceCollector`: H2O extension.
- `water/fvec/{H2OFrame,FrameOps}`: helpers in H2O's package namespace.
Packaged separately as `assembly-extensions` and shipped to external H2O clusters.

### `repl` (`ai.h2o.sparkling.repl`)
Embedded Scala interpreter (`H2OInterpreter`, `H2OIMain`, `BaseH2OInterpreter`, `PatchUtils`) powering the
Flow "Scala cell" feature through `core`'s `scalainterpreter` REST API.

### `core` (`ai.h2o.sparkling`, `ai.h2o.sparkling.backend.*`, `org.apache.spark.h2o.*`, `water.webserver.jetty9`)
Public entry points:
- `H2OContext` (object + class): `getOrCreate(conf)`, `asH2OFrame(df|rdd|ds)`, `asSparkFrame`, `asRDD`,
  `stop`, `flowURL`, `openFlow`, `setH2OLogLevel`, `getH2ONodes`; starts Flow proxy (`ProxyStarter`) and Spark UI tab.
- `H2OConf`: wraps `SparkConf`; mixes in `InternalBackendConf` + `ExternalBackendConf` (both extend `SharedBackendConf`,
  757 lines of `spark.ext.h2o.*` property getters/setters). Companion `H2OConf.checkSparkConf`.
  `*ConfExtensions` traits add derived helpers. Property docs are scraped from these files by `doc`/`booklet`.
- `H2OFrame` (REST handle to a frame: `split`, `join*`, `subframe`, `convertColumnsTo*`, `delete`, `apply(file|uri|frameId)`),
  `H2OColumn`, `H2OColumnType`.
- `DefaultSource`: Spark `DataSourceRegister` ("h2o" format) → `H2OFrameRelation`.
- `SparklingWaterDriver` / `SparklingWaterWithHiveDriver`: `main` classes for `bin/run-sparkling.sh`.

`backend/`:
- `SparklingBackend` trait (`startH2OCluster`, `backendUIInfo`, `epilog`) implemented by
  `org.apache.spark.h2o.backends.internal.InternalH2OBackend` (Spark RPC endpoints `H2ORpcEndpoint`,
  `SpreadRDDBuilder`, `InternalBackendUtils`) and `backend.external.ExternalH2OBackend`
  (YARN via `h2odriver` shell launch, Kubernetes via `K8sExternalBackendClient` + fabric8 `K8sH2OStatefulSet`/`K8sHeadlessService`).
- Data path: `converters/SparkDataFrameConverter.toH2OFrame` → `Writer.convert(H2OAwareRDD …)` → per-partition
  `Writer` (uses `ChunkAutoBufferWriter`, `insertToNode` REST upload) ; reverse: `H2ORDD`/`H2ODataFrame` → `Reader`
  (`ChunkAutoBufferReader`). `H2OAwareRDD`/`H2OAwareBaseRDD`/`H2OAwareEmptyRDD` pin partitions to H2O nodes.
  `SupportedRDD`/`SupportedDataset` + `*Converter` handle typed RDD/Dataset cases; `DataTypeConverter`,
  `CategoricalDomainBuilder`, `TimeZoneConversions`, `PartitionStats(Generator)`.
- `utils/`: `RestCommunication` (Gson-based `query/update/delete/insert/request`, SSL/basic-auth/Kerberos headers),
  `RestApiUtils` (typed wrappers for cloud info, log level, frames, jobs), `RestEncodingUtils`, `ProxyStarter` (Jetty
  reverse proxy for Flow), `SecurityUtils` (SSL/keystore), `SharedBackendUtils`, `H2OContextExtensions`,
  `ArgumentBuilder` (H2O CLI args), `AzureDatabricksUtils`, `ShellUtils`, `ReflectionUtils`, `SupportedTypes`, `ProgressBar`, `H2OFrameLifecycle`.
- `api/`: Jetty servlets exposed on the Spark driver for Flow (`rdds`, `dataframes`, `h2oframes`, `scalainterpreter`,
  `options`, `ShutdownServlet`); `ServletBase`, `ServletRegister`, `ParameterBase`.
- `exceptions/`: typed REST/cluster exceptions. `H2OJob`/`H2OJobStatus`: polling H2O jobs.
- `org.apache.spark.h2o.ui`: Spark UI tab (`SparklingWaterUITab`, `SparklingWaterInfoPage`, listener/events; Spark-version-specific parts in `scala_spark_*`).
- `water.webserver.jetty9`: `SparklingWaterJettyHelper`, LDAP login module.
Resources: `META-INF/services/org.apache.spark.sql.sources.DataSourceRegister`, `www/flow` CSS,
generated `spark.version`/`h2o.version`/`sw.version` (git-ignored).

### `api-generation` (`ai.h2o.sparkling.api.generation.*`) – the code generator
- Runners (`main(languageExt, destDir)`): `AlgorithmAPIRunner` (algos + params + Classifier/Regressor variants,
  Word2Vec), `MOJOModelAPIRunner` (MOJO models + metrics), `ConfigurationRunner` (Python/R `*BackendConf` from `H2OConf` getters/setters).
  Scala is skipped for `H2OAutoML`, `H2OGridSearch`, `H2OStackedEnsemble` (hand-written in `ml`).
- `common/`: `ConfigurationSource` implementations list H2O schema classes + explicit/deprecated/ignored fields:
  `AlgorithmConfigurations` (the big table: per algo → H2O `*ParametersV3` class, base trait, extra `ExplicitField`s),
  `FeatureEstimatorConfigurations`, `AutoMLConfiguration`, `GridSearchConfiguration`, `StackedEnsembleConfiguration`,
  `Word2VecConfiguration`, `MetricsConfigurations`. Resolvers (`ParameterResolver`, `OutputResolver`, `MetricResolver`)
  reflect over H2O schema classes; `IgnoredParameters`, `IgnoredOutputs`, `TypeExceptions`, `MetricFieldExceptions`,
  `ParameterNameConverter`/`MetricNameConverter` hold the special cases. `*SubstitutionContext` are the data passed to templates.
- `scala/`, `python/`, `r/`: string-template objects (`AlgorithmTemplate`, `ParametersTemplate`, `MOJOModelTemplate`,
  `ModelMetricsTemplate`, `MOJOModelFactoryTemplate`, `ConfigurationTemplate`, …). Templates are plain Scala string
  interpolation; there is duplication across the three language families.
- To add an algorithm/param: edit `AlgorithmConfigurations` (+ maybe hand-written `Has*` trait in `ml/params` and
  `*OnMOJO` in `scoring/params`), regenerate, add tests in `ml` and `py/tests`.

### `scoring` (`ai.h2o.sparkling.ml.{models,params,metrics,utils,internals}`) – MOJO scoring, no H2O runtime
- `H2OMOJOModel` (abstract, 727 lines + `H2OMOJOModelUtils` trait): loads MOJO via `H2OMOJOCache`/`H2OMOJOBaseCache`,
  exposes metrics/params/summary getters, `transform` via `H2OMOJOPrediction*` traits (one per model category:
  Binomial, Multinomial, Ordinal, Regression, Clustering, Anomaly, DimReduction, CoxPH, WordEmbedding) and
  `RowConverter`/`H2OMOJOFlattenedInput`. Subclass hierarchy: `H2OAlgorithmMOJOModel` → `H2OSupervisedMOJOModel` →
  `H2OTreeBasedSupervisedMOJOModel`; `H2OUnsupervisedMOJOModel` → `H2OTreeBasedUnsupervisedMOJOModel`;
  `H2OFeatureMOJOModel` bases for AutoEncoder/GLRM/Word2Vec/DimReduction/TargetEncoder. Concrete per-algo classes are generated.
- `H2OMOJOPipelineModel`: Driverless AI MOJO2 pipelines (tests gated by `testMojoPipeline` property + license).
- `H2OMOJOLoader`/`H2OMOJOReader`/`H2OMOJOWriter`/`H2OMOJOReadable`/`H2OMOJOWritable`: Spark ML persistence;
  `org.apache.spark.ml.util.expose.DefaultParams{Reader,Writer}` re-expose Spark-private helpers.
- `H2OMOJOSettings`, `H2OMOJOProps`, `HasMojo`, `SpecificMOJOParameters`, `PredictionWithContributions`/`StageProbabilities`.
- `params/`: ~30 custom `Param` types (`Nullable*Param`, `MapString*Param`, `NullableDataFrameParam`, `NullableMetricsParam`)
  plus `ParameterConstructorMethods` (used by generated params), `Has*OnMOJO` traits mirroring `ml`'s `Has*`.
- `metrics/`: `H2OMetrics` base, `H2OGLMMetrics`; concrete classes generated.

### `ml` (`ai.h2o.sparkling.ml.*`) – training (needs H2OContext)
- `algos/`: `H2OEstimator` → `H2OAlgorithm` (`fit` = convert to H2OFrame, POST `/3/ModelBuilders/<algo>`, poll job,
  download MOJO → `H2OAlgorithmMOJOModel`) → `H2OSupervisedAlgorithm` / `H2OSupervisedAlgorithmWithFoldColumn` /
  `H2OTreeBasedSupervisedAlgorithm` / `H2OUnsupervisedAlgorithm` / `H2OTreeBasedUnsupervisedAlgorithm`.
  Train-frame preparation mixins: `H2OTrainFramePreparation`, `DistributionBased…`, `FamilyBased…`.
  `classification/H2OClassifier`, `regression/H2ORegressor` + `*ForClassificationCheck` validators. Hand-written:
  `H2OAutoML`, `H2OGridSearch`, `H2OStackedEnsemble`, `H2OKMeansExtras`, `H2OAlgoCommonUtils`, `ProblemType`.
- `features/`: `H2OFeatureEstimator`, `H2ODimReductionEstimator`, `H2OAutoEncoderBase`, `H2OGLRMBase`, `H2OWord2VecBase`,
  `H2OTargetEncoder`, `ColumnPruner`.
- `models/`: `H2OBinaryModel` (H2O binary model download), `H2OTargetEncoderModel`, `HasBinaryModel`.
- `internals/H2OModel`: REST handle to a trained model (details, CV models, `toMOJOModel`).
- `params/`: `H2OCommonParams`, `H2OAlgorithmCommonParams`, `H2OAlgoParamsBase`, `H2OAutoMLParams`, `H2OGridSearchParams`,
  `DeprecatableParams`, `EnumParamValidator`, `ConversionUtils`, custom params (`HyperParamsParam`, `DictionaryParam`,
  `AlgoParam`, `Nullable*ArrayParam`) and ~25 `Has*` traits for fields with special handling (constraints, DataFrames, cols).
- `utils/`: `EstimatorCommonUtils`, `H2OParamsReadable`.
- Generated (`src-gen`): `H2O<Algo>`, `H2O<Algo>Classifier/Regressor`, `H2O<Algo>Params`, feature estimators.

## 5. Tests and conventions

- Scala tests: ScalaTest `FunSuite` + JUnit runner. Base traits in `core/src/test`: `SparkTestContext`
  (creates `SparkSession`, default conf, backend mode from sys prop), `SharedH2OTestContext` (adds `hc`, cluster size 1),
  `TestUtils`. `ml` tests reuse them through the `testArchives` configuration of `core`.
- Test naming: `*TestSuite.scala`; integration suites in `src/integTest`; benchmarks in `src/bench`.
- Python: pytest with fixtures in `conftest.py`; `algo_test_utils.py` has generic param-setter checks.
- Every algorithm gets: Scala `H2O<Algo>TestSuite`, Python `test_<algo>.py`, and MOJO parameter coverage in
  `MOJOParameterTestSuite` / `test_mojo_parameters.py`.
- `maxParallelForks = 1`; tests share a single H2O cloud per suite.
- Style: scalafmt (`.scalafmt.conf`, 120 cols, no alignment), google-java-format, spotless enforced in `check`.
- Version/deprecation: deprecated API via `DeprecatedMethodMacro`; `DeprecatableParams` for renamed params;
  `migration_guide.rst` documents breaking changes per release.

## 6. Refactoring hot spots and gotchas

- **Duplication across language templates** in `api-generation` (`scala/`, `python/`, `r/` template objects) and across
  `ml/params/Has*` vs `scoring/params/Has*OnMOJO` pairs. Changes to one side usually need the other.
- **`SharedBackendConf` + `Internal/ExternalBackendConf`** are large hand-maintained getter/setter files that also drive
  generated Python/R conf classes and docs; naming and doc comments are parsed by `ConfigurationRunner`.
- **Spark-version shims**: anything touching Spark private API lives under `org.apache.spark.*` packages or
  `scala_spark_*` dirs. Adding a Spark version = new `gradle-spark<X.Y>.properties` + possibly new shim dirs + CI matrix.
- **Generated `src-gen` dirs** are on the compile path but git-ignored; `compileScala.dependsOn(generateApi)`. IDE imports
  need a prior Gradle build.
- **`compileOnly` everywhere**: runtime deps come from Spark/H2O; adding a real dependency must be checked against the
  `assembly` exclude list and shaded if it conflicts with Spark.
- **REST coupling to H2O-3**: `RestApiUtils`, `H2OModel`, `H2OFrame`, extensions' handlers depend on H2O REST schemas
  (`*V3` classes from `h2o-core`/`h2o-algos`); H2O upgrades (`h2oMajorVersion`/`h2oBuild`) usually surface here and in
  `api-generation` ignore lists.
- `core/src/main/scala/ai/h2o/sparkling/backend/Writer.scala`, `H2OMOJOModel.scala`, `SupportedRDDConverterTestSuite.scala`
  hold most remaining TODOs (24 total in Scala/Python/R).
- Low churn: ~8 commits in the last two years; tags `RELEASE-3.46.0.x-1`. An untracked root `Dockerfile` (chainguard JDK +
  assembly jar) exists locally and is not part of the repo.
